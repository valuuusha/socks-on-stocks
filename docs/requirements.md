# Socks on Stocks — Технічне завдання

## 1. Загальний опис проєкту

**Резюме ідеї:** Проєкт являє собою сучасний кросплатформний десктопний застосунок (Windows/macOS), розроблений для фотографів та творців візуального контенту. Застосунок призначений для оптимізації рутинного процесу підготовки та одночасної відправки файлів на стокові платформи. Він поєднує в собі інструмент для зручного редагування метаданих (тегів, назв, описів) та надійний FTP-клієнт для масового завантаження файлів на сервери стокових агентств.

**Мета проєкту:** Створити швидкий, інтуїтивно зрозумілий та безкоштовний інструмент, який спростить робочий процес контриб'юторів. Основна мета — позбавити користувача необхідності використовувати кілька різних програм для тегування та завантаження, а також надати гнучку систему управління конфліктами метаданих (локальний файл vs база даних).

**Очікувані результати (на етапі 6 тижнів):**

- Готовий інсталяційний пакет застосунку для Windows та macOS.
- Функціонуючий інтерфейс користувача (GUI), що дозволяє працювати з галереєю зображень.
- Надійна система зчитування та запису метаданих без пошкодження оригінальних файлів.
- Працюючий модуль FTP для успішної передачі файлів на сервери з відображенням прогресу.

У межах MVP команда зобов'язується реалізувати базову версію десктопного застосунку, яка дозволяє користувачу імпортувати файли, редагувати основні метадані та завантажувати файли на FTP-сервер.

## 2. MVP

### Модуль 1: Робочий простір та управління файлами

- Забезпечення кросплатформної роботи десктопного застосунку на ОС Windows та macOS.
- Імпорт локальних файлів (зображень у форматі JPEG) з диска до робочого простору застосунку.
- Перегляд базових атрибутів кожного файлу: назва, формат, розмір.
- Створення, перейменування та видалення внутрішніх папок (альбомів) у межах робочого простору для логічного структурування контенту.
- Можливість розподілу та переміщення імпортованих файлів між створеними папками.
- Відображення списку або галереї імпортованих файлів у робочому вікні з урахуванням обраної папки.

### Модуль 2: Редактор метаданих та управління даними

- Надання інтерфейсу для редагування метаданих обраного файлу або групи файлів (Назва, Опис, Ключові слова).
- Локальне збереження внесених змін у вбудовану базу даних для фіксації прогресу між робочими сесіями.
- Експорт бази даних: реалізація функції вивантаження поточних даних проєкту (назви файлів та пов'язані з ними теги/метадані) у файл формату CSV.
- Імпорт бази даних: реалізація функції завантаження даних із зовнішнього CSV-файлу. Під час імпорту система повинна надавати користувачеві вибір: повністю перезаписати існуючу базу даних або дописати нові дані до існуючих без видалення поточної інформації.
- Експорт метаданих у файл: реалізація можливості фізичного запису відредагованих метаданих (EXIF/IPTC/XMP) безпосередньо у вихідний JPEG-файл із постійним відслідковуванням його актуального розташування на диску комп'ютера.
- Робоча область iStock: створення вікна для розумної роботи з тегами (визначення релевантності, розумна вставка та масове застосування найбільш релевантних тегів на початок списку для обраних картинок).

### Модуль 3: FTP-менеджер та мережева взаємодія

- Створення, редагування та збереження профілів підключення до FTP-серверів (хост, порт, логін, пароль, цільова директорія).
- Ініціалізація підключення до сервера з використанням обраного профілю.
- Масове завантаження обраних файлів на FTP-сервер.
- Візуалізація процесу передачі даних: відображення статусів "очікує", "завантажується" (з індикатором прогресу), "успішно завантажено" та "помилка".
- Ведення локального журналу операцій для фіксації помилок та успішних транзакцій.

### Модуль 4: Локальна безпека та управління сесіями

- Реалізація локальної авторизації: встановлення пароля або пін-коду при першому запуску програми для захисту доступу до робочого простору на конкретному комп'ютері.
- Налаштування тривалості сесії: можливість вибору терміну дії активної сесії користувача.
- Автоматичне завершення сесії: примусовий вихід із профілю (логаут) після спливу встановленого терміну або заданого часу неактивності, з вимогою повторної локальної авторизації для відновлення доступу.

## 3. Нефункціональні вимоги

### 1. Надійність завантаження

Під час масового FTP-завантаження помилка передавання одного файлу не повинна перервати завантаження інших файлів у черзі. Застосунок має завершувати обробку всієї черги файлів навіть у разі помилок окремих елементів. Для кожного файлу має зберігатися окремий результат операції, щоб після завершення процесу система могла відобразити підсумок успішних і неуспішних завантажень.

### 2. Кросплатформність

MVP-версія застосунку має запускатися щонайменше на Windows 10/11 та macOS 12 (Monterey) і новіше. Інтерфейс має зберігати однакову структуру на обох платформах.

### 3. Продуктивність

Застосунок має відкривати робочий простір із 100 локальними файлами розміром до 45 МБ кожен не довше ніж за 5 секунд на комп'ютері з мінімум 8 ГБ оперативної пам'яті. Під час редагування метаданих інтерфейс не повинен зависати більше ніж на 1 секунду після зміни значення в полі назви, опису або тегів.

### 4. Безпека локальних даних

FTP-паролі та пін-код користувача не повинні зберігатися у відкритому текстовому вигляді. Після збереження FTP-профілю пароль не має відображатися в інтерфейсі як звичайний текст. Після завершення активної сесії або після вибраного користувачем періоду неактивності застосунок має вимагати повторне введення пін-коду для доступу до робочого простору.

### 5. Цілісність локальних файлів

Під час імпорту, перегляду та видалення з робочого простору застосунок не повинен безпідставно пошкоджувати оригінальні файли. Запис метаданих є єдиною дозволеною операцією модифікації файлу, яка може незначно змінити його кінцевий розмір, але при цьому візуальна частина зображення (піксельні дані) має залишатися абсолютно незмінною і не втрачати якість.

### 6. Локалізація

Інтерфейс застосунку виконано англійською мовою. Підтримка інших мов у межах MVP не передбачена.
